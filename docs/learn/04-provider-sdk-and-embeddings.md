# Provider SDK and embeddings

A provider SDK is the direct contract with the model: authentication, request shape, retries, structured output, and token usage in the response. Calling it directly, as this module does, shows exactly what frameworks wrap. An embedding model maps text to a vector so that texts with similar meaning land close together; cosine similarity between vectors is the measure, and the vector length (here 1536) is fixed by the model, so it is one constant in configuration. The model reads at most 8,191 tokens per input; a full blog post can be longer, so the embedded text is clipped (the full text stays stored for keyword search), and one vector for a long post blurs its meaning, which is what chunking (splitting a document into passages, each with its own vector) solves later. Structured output asks the model to return JSON that matches a schema (here a Pydantic model), so the code parses data instead of guessing at prose. Every call is charged to a ledger with a hard cap, because an unbounded loop over a paid API is a production incident.
