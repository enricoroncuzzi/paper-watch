# Sources and licensing

Data you build on must be data you may use. arXiv dedicates its descriptive metadata, abstracts included, to the public domain (CC0), so abstracts may be stored, embedded, and quoted; the PDFs stay under each author's licence, so this system never downloads them. A paper can appear in several versions (`v1`, `v2`): identity is the base id without the version, otherwise the same paper is stored twice.

arXiv's daily harvest uses its OAI-PMH bulk interface, the metadata pipeline arXiv recommends for keeping an up-to-date copy, rather than the search API. OAI-PMH pages a result set with resumption tokens: a `ListRecords` request names a metadata format (`arXivRaw`, which carries every version and its exact date), a set, and a datestamp window, and a response may end with a `resumptionToken` that the next request sends instead of the original parameters. The datestamp is a record's last-modification time, so harvesting day by day sees a paper once it is announced and sees it again when it is revised. A set is an archive (`cs`) or one of its sub-archives (`stat:stat:ML`), so a profile's categories are turned into the sets to ask for. Both interfaces ask for at most one request every three seconds on one connection, and the client honours a `Retry-After` header once before it stops for the day rather than hammering a busy server: a polite client enforces all of this in code rather than hoping the volume stays low.

A preprint is not peer-reviewed, so reliability needs evidence. Two signals are cheap and honest: community attention (Hugging Face daily papers, a curated list of arXiv ids with upvotes) and scholarly uptake (Semantic Scholar's venue of publication and citation count). Semantic Scholar's data carries its own licences and requires attribution when displayed; this system uses it for ranking and labelling, never as quoted text.
