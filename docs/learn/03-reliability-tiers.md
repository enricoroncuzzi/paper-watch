# Reliability tiers

Retrieval can only be as trustworthy as what it retrieves. Each stored item carries a reliability tier decided by explicit, testable rules, never by a model's impression: peer-reviewed when a recognised venue accepted it, vetted preprint when there is independent evidence of quality (community upvotes or citations), lab blog when it comes from an official engineering feed. Because the tier is data, later stages can filter by it and a post can state "peer-reviewed at ICLR" or "a preprint" truthfully. Evidence arrives late (upvotes over days, citations over weeks, a venue acceptance after months), so the rules are re-applied as it grows, and a tier only ever goes up: an outage or a lagging answer must not demote a paper.

A known lab team's arXiv author string is weaker than community evidence: it is an authority signal, not independent proof of quality, so it is named "same-day admission for lab reports". It lets a flagship report enter as a vetted preprint on day one, before the community upvotes it would earn anyway, and it is the only route for teams whose papers get little attention. Every admission records which rule fired as its basis, so a lab's own report stays distinguishable from community-vetted work and retrieval or a draft can say which one it is. Because admission never lowers a tier, a later policy change (a higher relevance threshold, a dropped venue or author string) never removes or demotes anything already stored: removing an item needs an explicit migration.
