# Classifier evaluation and calibration

A classifier is judged per class on a labelled set. Precision is the share of items it put in a class that belong there, recall is the share of a class's items it found, and F1 is their harmonic mean, which is high only when both are. Macro averaging takes the plain mean over classes, so a small class counts as much as a large one. For a corpus, the number that matters most is admitted precision: of everything let in, how much was right. A similarity classifier also needs a threshold per class, and the threshold is a fitted parameter. Choosing it and measuring it on the same examples overstates quality, so the labelled set is split once. The validation half chooses each threshold, here the cut with the best F1, placed halfway to the nearest rejected score. The test half then measures what was chosen, standing in for papers the classifier has never seen. Even then, two cautions hold. On a few hundred examples one changed answer moves a class's F1 by several points, so differences smaller than a bootstrap interval are noise. And every choice made by looking at validation (a reworded description, a new threshold rule) makes validation look better than the future will be, which is why the gap between validation and test is worth reading. Calibration is therefore a recorded run, not a hand edit. The thresholds, the descriptions, the model and the labels are bound by one fingerprint, so a test fails when any of them changes without rerunning it. The checks split by what they can prove. Offline tests with a fake embedder prove the arithmetic: threshold choice, scoring, the gate and the file update. Only the real model can prove the scores, so that gate runs in its own job.
