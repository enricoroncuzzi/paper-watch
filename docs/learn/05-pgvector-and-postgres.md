# pgvector and Postgres

pgvector adds a `vector` column type and distance operators to Postgres, so embeddings live next to the data they describe, in one transactional store with one backup. Exact nearest-neighbour search compares the query with every row; an HNSW index builds a navigable graph of neighbours so a query visits only a small part of it, trading a little recall for large speed. Full-text search (`tsvector`, `websearch_to_tsquery`, GIN index) finds exact terms that embeddings blur, such as model names. Uniqueness constraints, not application code, are what make ingestion idempotent: the database refuses a duplicate even if two runs race. Check constraints keep the record honest in the same way: an admitted item without a tier or an embedding cannot be written. A partial index covers only the rows a query can return (here, admitted items), and Postgres uses it only when the query's condition matches the index's condition, which is why the search query repeats that condition literally.
