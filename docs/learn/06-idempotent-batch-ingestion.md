# Idempotent batch ingestion

A batch job in production must be safe to run twice, safe to crash, and honest about what it did. Safe to run twice: each source keeps its own cursor (the end of its last fully successful fetch), and the database's unique key refuses duplicates, so overlapping windows cost nothing. Safe to crash: each item commits in its own small transaction, so a failure loses at most one item, and that item is written to a dead-letter table with enough data to retry it. Recovery is automatic: a source that failed keeps its old cursor, so the next run fetches the missed window again, and every open item dead letter is retried and marked resolved when it succeeds. Honest: every run writes a record with its status (`succeeded`, `partial`, `budget_exhausted`, `failed`), counts, and tokens, so silence is never mistaken for success; a run that finds another run already holding the single-run advisory lock writes no record at all and exits as `skipped`, because the other run is doing the work. Safe against late data: arXiv is harvested one datestamp day at a time, and each response page is stored durably before the next request goes out, so a crash loses at most the page in flight; the cursor advances only once a whole day is complete, and a completed day is never re-read except for the one day of overlap that absorbs a datestamp's time-zone boundary, which the unique key makes free to repeat. Honest about optional data: a quality-signal source that fails does not abort the run, but it is recorded and the run is marked partial, so a silent outage cannot pass for a quiet day; a source-outage letter is written once, and the run where that source answers again closes it (for arXiv, a completed day closes it too), so a long outage with no completed day leaves one open letter instead of one per day; a run that finishes a day and then fails closes that letter and opens a fresh one for the remaining outage. All business timestamps come from the run's `now`, never the database clock, so a run's start, finish and resolved letters are a deterministic sequence. Patient with late evidence: a paper's credibility grows for weeks or months after it appears, so every relevant paper is kept as a candidate and every run re-checks the evidence of the papers whose tier can still rise and whose re-check is due, more often while they are young, deciding on everything known so far and never moving a tier down. Bounded retries: an item that fails the same way three times is set aside as a dead letter for a human, so a poison item cannot make every future run partial. Safe against poison: an entry that can never be parsed is recorded once as a dead letter and the cursor still advances, so one bad record cannot block a source forever. Judged, not just run: a job that runs every day ends each run with a health verdict, because a run that technically succeeded can still be wrong, for example an arXiv fetch that returned nothing. A budget stop ends the run before its evidence re-checks, so that run's promotions and admittances wait for the next one.
