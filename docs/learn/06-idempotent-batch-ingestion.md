# Idempotent batch ingestion

A batch job in production must be safe to run twice, safe to crash, and honest about what it did. Safe to run twice: each source keeps its own cursor (the end of its last fully successful fetch), and the database's unique key refuses duplicates, so overlapping windows cost nothing. Safe to crash: each item commits in its own small transaction, so a failure loses at most one item, and that item is written to a dead-letter table with enough data to retry it. Recovery is automatic: a source that failed keeps its old cursor, so the next run fetches the missed window again, and every open item dead letter is retried and marked resolved when it succeeds. Honest: every run writes a record with its status (`succeeded`, `partial`, `budget_exhausted`), counts, and tokens, so silence is never mistaken for success. Safe against late data: arXiv's query filters by submission date, but a paper appears only once it is announced, hours or days later, so every run re-reads the seven days before its cursor; the overlap costs a few requests and the unique key absorbs it. Honest about optional data: a quality-signal source that fails does not abort the run, but it is recorded and the run is marked partial, so a silent outage cannot pass for a quiet day. Patient with late evidence: a paper's credibility grows for weeks or months after it appears, so every relevant paper is kept as a candidate and every run re-checks the evidence of the papers whose tier can still rise and whose re-check is due, more often while they are young, deciding on everything known so far and never moving a tier down. Bounded retries: an item that fails the same way three times is set aside as a dead letter for a human, so a poison item cannot make every future run partial. Safe against poison: an entry that can never be parsed is recorded once as a dead letter and the cursor still advances, so one bad record cannot block a source forever. Judged, not just run: a job that runs every day ends each run with a health verdict, because a run that technically succeeded can still be wrong, for example an arXiv fetch that returned nothing.
