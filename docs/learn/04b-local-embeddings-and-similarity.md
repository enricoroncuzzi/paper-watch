# Local embeddings and similarity classification

Production embeds on its own machine. An embedding model is a fixed file of weights: ONNX Runtime executes it on the CPU with no network, no API key and no price per call, and fastembed wraps it together with its tokenizer. Running locally trades a hosted model's scale for three properties a corpus needs: the model cannot change under you (vectors from two models live in different spaces and cannot be compared, so changing the model means re-embedding everything), each item costs nothing, and ingestion keeps working when a provider is down. On a small server the constraint is memory, not speed: a transformer's working memory grows with the batch and with the input length, so the embedder takes one text at a time, clips long inputs, and turns off ONNX Runtime's memory arena, which would otherwise keep freed memory for reuse. The same vectors also classify. Each topic profile has a written description; an item's cosine similarity to that description says how well it fits, and a per-profile threshold turns the score into a yes or no. The threshold is chosen on a labelled set to maximise F1, the balance of precision (how many admitted items are right) and recall (how many right items are admitted), and it belongs to one model, because every model spreads its cosines over a different range. So the threshold, the description and the model are calibrated and versioned together, and the code refuses to apply the thresholds to any other model.
